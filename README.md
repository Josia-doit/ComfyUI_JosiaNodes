## 📋 节点列表与功能说明

### 1. Josia文本编码（JosiaEncoder）
- **分类**：⚡️JosiaNodes
- **核心功能**：文生图 + 图生图一体化 CLIP/VAE 编码，最多融合 5 张参考图
- **输入**：
  - CLIP、VAE（可选）
  - 图像1~5（可选，最多 5 张参考图）——**按需展开**：默认只显示「图像1」，接入一张后自动出现「图像2」，依次最多 5 张；断开后自动收起多余的端口
  - 正向提示词、负向提示词
- **输出**：正向条件 / 负向条件 / Latent
- **核心开关**：
  - **图像参考模式**：开启 = 图生图模式（图像经 VAE 编码为 Latent），关闭 = 文生图模式（输出空 Latent）
  - **参考 Latent 模式**：开启 = 注入参考 Latent 条件（模型参考原图特征），关闭 = 标准 VAE 编码（纯文本条件驱动图生图）
  - **负向提示词生效**：开启 = 负向提示词正常编码，关闭 = 负向条件自动归零
- **四种工作模式**：

  | 状态 | 图像参考模式 | 参考 Latent 模式 | Latent 输出 | 条件输出 |
  |------|:---:|:---:|---|---|
  | 文生图 | 关 | — | 1024×1024 空画布 | 纯文本条件 |
  | 文生图（带图尺寸） | 关 | — | 原图尺寸空画布 | 纯文本条件 |
  | 标准图生图 | 开 | 关 | VAE 编码 Latent | 纯文本条件 |
  | 参考图生图 | 开 | 开 | VAE 编码 Latent | 参考 Latent 条件 |

- **特点**：VAE 端口可选（未接入时自动降级为空 Latent）、原生逻辑兼容 Flux / 千问等模型

### 2. Josia文本列表（JosiaTextList）

- **分类**：⚡️JosiaNodes
- **核心功能**：将多行字符串按分隔符分割为字符串列表，支持多种过滤和显示模式
- **输入**：文本（多行字符串，支持上游文本节点连接）
- **输出**：prompt_list（字符串列表）
- **可选设置**：
  - 过滤空行（默认开启）：自动去除分割后的空行
  - 修剪空白（默认开启）：去除每行首尾空格、制表符等空白字符
  - 分隔符（默认 `\n`）：支持 `\n`（换行）、`\t`（制表）、逗号、分号等自定义分隔符；**留空则不分割**，整段文本作为单条输出（适合把本节点当纯文本框显示任意内容，无需塞无意义分隔符）
  - 去重过滤（默认关闭）：自动去除重复行，保持原始顺序
  - 正则过滤：支持正则表达式筛选匹配的行，内置 11 种自定义快捷规则：
    - `/汉字/` 匹配中文 | `/汉字开头/` 匹配以汉字开头 | `/纯汉字/` 纯中文行
    - `/英文/` 匹配英文 | `/数字/` 匹配数字 | `/空行/` 匹配空行 | `/空格/` 匹配空格
    - `/序号行/` 匹配带序号行 | `/标签行/` 匹配标签行
    - `/?文本/` 万能匹配（如 `/天空/` 匹配含"天空"的行）
    - `/?文本开头/` 万能开头匹配（如 `/天空开头/` 匹配以"天空"开头的行）
  - 显示模式：列表模式（每段文本一个显示框）/ 完整文本（合并为一段显示）
- **适用场景**：
  - 提示词批量处理：将多行提示词逐行拆分为独立条目
  - 提示词筛选：过滤 LLM 输出的序号行（如 `[prompt 1]`），只保留有效提示词
  - 路径列表拆分：将多行路径字符串拆分为路径列表
  - 配置项拆分：将多行配置文本按自定义分隔符拆分
- **特点**：纯 Python 标准库实现，零依赖；节点下方自动扩展预览窗口，直观显示分割结果

### 3. Josia文本保存（JosiaTextSave）

- **分类**：⚡️JosiaNodes
- **核心功能**：将文本内容保存到文件，支持通配符解析、输出目录指定、图像文件名复用
- **输入**：
  - 文本（多行字符串，支持上游节点连接）
  - 图像（可选，接入时自动复用原图文件名）
- **输出**：输出文本（透传输入文本，方便串联）
- **参数**：
  - 选择输出目录：点击「选择输出目录」按钮打开**内置文件夹浏览器**（支持磁盘列表、ComfyUI 输出/输入目录快捷入口、桌面与用户目录、上级导航、路径直接输入跳转、新建文件夹、最近使用记录）；也可直接手填 / 粘贴路径（置于文本输入框之后，符合「先选目录」的使用惯性）
  - 输出路径：浏览器选中的目录路径，也可手动输入或粘贴
  - 文件名：支持通配符（%date%/%time%/序号等）
  - 保存格式：txt / csv
  - 打开输出目录：保存后可一键在系统文件管理器中打开该目录（Windows 生效）
  - 复制路径：一键将当前输出目录复制到剪贴板（非 Windows 平台或需把路径贴到别处时使用）
- **关于文件夹选择器与注册表分发**：旧版本通过脚本宿主调用系统文件夹选择对话框，会命中 ComfyUI 注册表的自动安全扫描，导致 1.5.5~1.6.4 全部被判 `Banned`；`1.6.7` 移除外部进程后降级为 `Flagged`（人工复核）仍未放行。因此 `1.7.0` 起**功能优先**——文件夹选择保持「内置文件夹浏览器」（后端标准库 `os.scandir` 枚举 + 前端浮层渲染），同时恢复「打开输出目录」按钮（后端 `os.startfile`，Python 标准库、非子进程）。本包以 **GitHub 直接分发**（git clone / 手动拷贝）为主渠道，不保证通过 ComfyUI 注册表的自动扫描
- **稳定性**：重启 ComfyUI 后各参数正确保存，不再因前端按钮序列化导致字段错位（路径串入文本 / 通配符乱跳）
- **通配符规则**（成对 %xxx% 解析）：
  - `%date%` → 2026-06-30
  - `%time%` → 07:38:41
  - `%date:yyMMdd%` → 260630
  - `%003%` → 3位序号从003开始
- **文件名冲突处理**：同名文件自动追加 _001、_002 等编号
- **特点**：支持 CSV 格式（自动添加 UTF-8 BOM，Excel 友好）；纯 Python 标准库实现，零依赖

### 4. Josia多图加载（JosiaMultiImageLoader）
- **分类**：⚡️JosiaNodes
- **核心功能**：批量加载多张图片，支持选择文件 / 拖拽 / 粘贴，每张图独立等比缩放
- **输入**：
  - 图片路径（前端图库区自动管理，无需手动输入）
  - 上游图像（可选，串联模式：上游图像插入本节点图像之前合并输出）
  - 缩放模式 / 百万像素 / 缩放步数 / 边长方向 / 边长值 / 缩放算法 / 对齐倍数
- **输出**：
  - `images_out`：汇总输出。
    - **列表模式**：返回全部 N 张图的 list，配合 ComfyUI 原生 list 展开（`OUTPUT_IS_LIST`），下游（如 llama.cpp 反推）**自动逐张执行 N 次**——一次排队 = 全部图像打完标，无需手动批次按钮、无需序号递增。混合比例时自动 letterbox。
    - **批次模式**：返回合并 batch（所有图像拼为一个 batch，混合比例时自动 letterbox）。
  - `image_1` ~ `image_N`：每张图独立输出（各自正确的等比缩放尺寸，无黑边无拉伸）
- **按图片数量自动跑 N 次**：列表模式下 `images_out` 以 list 形式输出，ComfyUI 自动把下游节点展开为「每张图一次」，特别适合「多图加载 → 反推打标 → 文本保存」的批量字幕工作流（输出与图像同名，txt 边跑边写）
- **缩放模式**（原生 BOOLEAN 开关，全中文参数名）：
  - 🖼️ **按像素缩放**：按总像素目标等比缩放（参考原生 ImageScaleToTotalPixels），每张图独立计算
  - 📐 **按边长缩放**：按长边或短边等比缩放，另一方向自动适配
    - ➡️ 按长边缩放 / ⬇️ 按短边缩放
- **缩放步数**（N 步渐进缩放）：
  - 默认 1 = 一步到位（最快）
  - 2~16 = 分步渐进缩放，大比例缩小时减少锯齿和伪影，质量更好
- **高级特性**：
  - 6 种缩放算法（lanczos / nearest / bilinear / bicubic / area / nearest-exact）
  - 尺寸对齐倍数（0 / 8 / 16 / 32），适配 VAE 编解码
  - 绝对路径去重，防止同名不同目录的图片重复载入
  - 缩放值=0 表示不缩放，原图直出
- **前端图库**：
  - 自适应缩略图网格（参考对标节点 optimizeGrid 算法，无限缩放）
  - 节点尺寸随图库区域自动变化（wasFresh 检测 + force-shrink 机制）
  - 支持文件选择 / 拖拽 / 粘贴三种来源
  - 滚轮缩放、分辨率标签显示、一键排序 / 清空 / 重置参数
- **特点**：使用 ComfyUI 标准 `/upload/image` API，原生 BOOLEAN 开关（不破坏 ComfyUI 布局），全中文参数名

### 5. Josia图像缩放（JosiaImageScaling）
- **分类**：⚡️JosiaNodes
- **核心功能**：全能图像缩放裁切，支持「选择比例」下拉 + 3 种自定义模式
- **输入**：图像（可选）、遮罩（可选）
- **输出**：图像 / 遮罩 / 宽度 / 高度
- **选择比例**（默认「关」，共 9 种比例）：
  - 1:1 正方形 / 2:3 竖屏 / 3:2 横屏 / 3:4 竖屏 / 4:3 横屏 / 9:16 竖屏 / 16:9 横屏 / 21:9 超宽屏 / 9:21 竖超宽
  - **比例与缩放模式可同时生效、互不覆盖**：比例决定**目标宽高比**（输出框形状），缩放模式决定**尺寸量级**
  - 选定比例且**未开启任何缩放模式** → 按接入图的像素面积适配新比例（保持面积、精确比例）
  - 不接图像（允许空挂）→ 输出目标尺寸的**纯色图**；不接输出图时也可当作**分辨率选择器**提供宽度 / 高度数值
- **缩放模式**：
  - 📏 边长缩放（按最长/最短边；选定比例时按比例的对应边计算）
  - 🖼️ 像素缩放（按百万像素自动算尺寸，最高优先级；选定比例时按比例算宽高）
  - ✏️ 手动宽高（支持一键切换宽高；显式指定，优先于比例）
- **裁剪方式**：
  - 裁切 / 拉伸类：中心裁剪 / 对齐上边 / 对齐下边 / 对齐左边 / 对齐右边 / 拉伸缩放
  - **扩展并填充类**：扩展并填充**白 / 黑 / 绿 / 蓝 / 灰** —— 当设定比例与原图不同时**不裁切画面**，而是按目标比例扩展画布并填充指定纯色、原图等比居中贴合。适合图像扩展 / 外补绘，绿 / 蓝可直接作 chroma key 占位，灰为中性底板
- **高级特性**：
  - **边长倍数对齐**（默认 **16**，可选 关 / 2 / 4 / 8 / 16 / 32 / 64 / 128）：把输出宽高对齐到该倍数的整数倍（16 适配绝大多数 VAE 潜空间）
    - 仅一边不是倍数 → **只裁切那一边**、不做缩放（例：1536×2732 → **1536×2720**，长边裁掉 12px，宽保持原样）
    - 两边都不是倍数 → 以**短边为基准等比缩小**后再对齐（例：1500×1000 → **1488×992**，宽高比不变）
    - 全程**只裁切或缩小、绝不放大**；短边不足一格时放弃对齐（而不是放大到一格）
  - 5 种缩放算法（nearest / bilinear / area / bicubic / lanczos）
  - 渐进式多步缩放，低像素更清晰（「扩展并填充」自动跳过渐进，避免中间步拉伸变形）
  - 自动分辨率保护，上限 400 万像素 —— **仅在主动设定了尺寸 / 比例时生效**，纯透传不缩放
- **鼠标悬停提示**：全部参数均带中文 tooltip，鼠标指向控件即显示该参数的作用、取值范围与生效条件
- **特点**：不设置任何尺寸时图像仅按「边长倍数」对齐后透传（不会因分辨率上限被动缩小）；无图像输入且未设尺寸时输出 **1024×1024 白色图片**（选「扩展并填充XX色」则输出对应纯色底板），宽度 / 高度输出同步为该分辨率

### 6. Josia图像对比（JosiaImageComparer）
- **分类**：⚡️JosiaNodes
- **核心功能**：双图实时对比预览，支持两种交互模式；并输出 A/B 左右无缝拼接图
- **输入**：image_a、image_b（均为可选）
- **输出**：拼接图像（IMAGE）——把图像A与图像B沿宽度方向左右无缝拼接成一张图
  - 两图高度不一致时，自动把 B 等比缩放（lanczos）到与 A 同高再拼接，避免错位 / 黑边
  - 通道数自动对齐：RGBA（4通道）与 RGB（3通道）混接时自动补不透明 alpha，解决新版 ComfyUI LoadImage 默认 3 通道导致的拼接崩溃
  - 只接一张图则原样输出；都不接输出空
- **模式（胶囊控件，与媒体保存节点同款样式）**：
  - 胶囊①`滑动对比 ｜ 点击对比`（默认**滑动对比**）：滑动＝鼠标移动出现竖直分割线，左 A 右 B；点击＝按住显示 B 图，松开恢复 A 图
  - 胶囊②`默认 ｜ 等宽 ｜ 等高`（默认**默认**）：`默认`＝每张图**各自**以完整可见的最大比例适配显示区（横版图吃满宽度、竖版图吃满高度，互不拖累、各自居中）；`等宽`＝两图同宽、高度按各自比例；`等高`＝以 A 填满可用区、B 缩放到同高（B 更宽时超出部分被裁剪）
  - 数字框③`混合`（默认 0）：上层图像 B 的不透明度（0=关闭，100=完全覆盖）；大于 0 时把 B 叠在 A 上显示两张图重叠效果，替代滑动/点击对比。支持手动输入、滚轮与上下箭头（步进 5），数值钳制在 0~100
  - 切换**实时生效**（图元已缓存，无需重新执行节点）；两项只影响**节点内预览**，输出拼接图仍按高度适配（见上）
  - 右键菜单与其它节点完全一致（未做任何额外菜单改写）
- **特点**：继承官方 PreviewImage、自动保存、前端渲染流畅、支持拉大节点舒适对比；画布对比层与拼接输出口互不干扰
- **渲染结果留存**：执行出来的对比图在**撤销、切换工作流、刷新页面（F5）**后依然保留，不用重新执行
  - 原理：对比图本就保存在 ComfyUI 的 `temp` 目录，只要服务进程没重启文件就一直在；节点被重建时按记录的文件名自动重新取回
  - 记录只写在浏览器本地（localStorage），**不写入工作流文件** —— 不会把工作流标记为「已修改」，也不占用撤销历史
  - 边界：**重启 ComfyUI 会清空 `temp`**，此时图像文件本身已不存在，需重新执行（与官方 Preview 类节点一致）

### 14. Josia媒体保存（JosiaMediaSave）
- **分类**：⚡️JosiaNodes
- **核心功能**：一个节点吃下所有 AIGC 产物——图像 / Latent（自带 VAE 解码）/ 图像批次合成视频 / 音频 / Latent 落地，全部按**原生同名节点的落盘方式**复刻，图像还能继续向下游输出
- **输入**：
  - `图像`（IMAGE，可选）— 直接显示 + 保存，同时透传下游（平替原生 Save Image / Preview Image）
  - `Latent`（LATENT，可选）+ `VAE` — 节点自带解码，免接独立的 VAE Decode 节点
  - `音频VAE`（VAE，可选）— 解码 `Latent` 里**音频路**用的 VAE（LTX / MiniMax H3 等双 VAE 模型）
  - `视频`（VIDEO，可选）— 已有的视频对象按所选容器原样转存
  - `音频`（AUDIO，可选）— 落盘为 FLAC / WAV（无损）/ MP3 / Opus
  - ⚡ **可连线参数**：`文件名` / `帧率` / `质量` 保留了输入端口，可用上游节点（整数 / 文本等）直接驱动；其余参数在画布上调节即可
- **输出**：`图像`（IMAGE，透传 / 解码结果）、`路径`（STRING，主文件相对路径）、`Latent`（LATENT，原样透传输入 Latent，便于双采样器等工作流二次利用）、`Video_Latent` / `Audio_Latent`（LATENT，从联合 AV 潜空间拆出的视频路 / 音频路；非 AV 潜空间时为 None，可直接喂给下游双采样器 / 音频解码）
- **VAE 来源（打通「Josia模型加载」）**：
  - `VAE1` 下拉默认 **「使用Josia模型加载VAE」** —— 直接复用「Josia模型加载」节点已载入的 VAE，**不需要连线**；也可手动从 `models/vae` 里选一个另行加载
  - 一旦给 `VAE` 端口接了线，`VAE1` **自动灰化**（接线优先）
  - `VAE2`（= 音频 VAE）默认占位符「🎵 请选择模型…」= 不使用音频 VAE。**默认不显示**：`VAE1` 手动选了具体模型后才出现（自动补上占位符）；`VAE1` 保持默认、或给 `VAE` 端口接了线时都隐藏
  - 接了 `VAE` 端口 ⇒ `VAE1` **灰化**（以接线为准）、`VAE2` 隐藏；接了 `音频VAE` 端口 ⇒ `VAE2` 灰化
- **双 VAE 模型不会只解一半**：`Latent` 若是视频 + 音频的**联合 AV 潜空间**，会自动按官方语义分离（视频路取 `unbind()[0]`、音频路取 `unbind()[-1]`），分别用 `VAE1` / `音频VAE` 解码后**同时落盘**；检测到音频路却没给音频 VAE 时会**明确告警**，而不是静默丢掉音频
- **图像格式（15 种，名称前的 ⭐ 表示该格式可写入工作流元数据）**：

| 格式 | 扩展名 | 元数据 | 无损 | 备注 |
|---|---|---|---|---|
| ⭐ PNG | .png | ✅ | ✅ | 私有 chunk，原生同款 |
| ⭐ JPEG | .jpg | ✅ | — | EXIF UserComment |
| ⭐ WebP | .webp | ✅ | ✅ | EXIF |
| ⭐ TIFF | .tif | ✅ | ✅ | EXIF |
| ⭐ AVIF / HEIF / JPEG XL | .avif / .heif / .jxl | ✅ | ✅ | 需额外插件，缺插件时自动隐藏 |
| ⭐ JPEG 2000 | .jp2 | ✅ | ✅ | 可无损可有损 |
| BMP / TGA / PPM / PBM / ICO / DDS / PCX | .bmp / .tga / .ppm / .pbm / .ico / .dds / .pcx | — | ✅ | 无元数据容器 |

- **格式列表按环境自动裁剪**：只列出**当前环境真的能保存**的格式。缺插件的格式（AVIF / HEIF / JPEG XL）会**自动隐藏而不是报错**，装上插件重启后自动出现，无需改代码
- **视频容器**：`MP4`（H.264 / H.265 / AV1）· `MKV`（+ VP9）· `WebM`（VP9 / AV1）· `GIF` · `APNG` · `动图WebP`（视频格式下拉首项为「关」＝不输出视频）
  - 由**图像批次 + 帧率**合成；接入 `视频` 输入时按所选容器**原样转存**
  - 容器放不下的编码会**自动换成该容器的默认编码**（例如 WebM + h264 → 自动改用 VP9），不会报错
  - 选视频容器时**不额外导出单帧静图**（与原生 Save WEBM / SaveAnimated* 行为一致）
- **音频格式**：`FLAC` / `WAV`（无损，WAV 为 pcm_s16le 16-bit PCM、无码率）/ `MP3` / `Opus`，名称前带 ⭐ 的格式**支持写入工作流元数据**（FLAC / MP3 / Opus；WAV 不写）；码率 64k / 96k / 128k / 192k / 320k（`音质` 下拉；选无损格式时灰化显示「无损」；格式下拉首项为「关」＝不输出音频）
- **潜空间落地**：`保存潜空间` 开关，额外把 `.latent` 存成与原生 Save Latent 相同的格式；**解码前优先落盘（OOM 保护）**——先存盘再解码，即使解码爆显存数据也不报废，可用「Josia加载Latent」节点重新加载、释放显存后单独解码续上
- **解码（自带 VAE Decode + 分块解码）**：
  - `解码方式`：**自动** = 先直接解码，触发 OOM 时自动改用分块解码重试；也可显式指定**直接解码**或**分块解码**
  - 分块参数为**规范值下拉**（避免手误）：`分块大小` 256 / 384 / 512 / 768 / 1024 / 1536 / 2048（默认 512）· `空间重叠` 0 / 32 / 64 / 96 / 128 / 192 / 256（默认 64）· `解码批次` 8 / 16 / 32 / 48 / 64 / 96 / 128（默认 64）· `帧间重叠` 4 / 8 / 12 / 16 / 24 / 32（默认 8）—— 逐字复刻原生 VAEDecodeTiled 语义（含视频 VAE 的时间分块换算）；UI 内部标签为「分块大小 / 空间重叠 / 解码批次 / 帧间重叠」，后端参数名仍为 `分块尺寸 / 分块重叠 / 时间分块 / 时间重叠`
  - `解码精度`：自动 / fp32 / fp16 / bf16，专治黑图、雪花屏
- **缓存清理**：`清理缓存`（关 / 轻度 / 深度）+ `清理时机`（解码前 / 解码后，默认解码前）
  - **只回收无引用张量与 CUDA 空闲块，绝不卸载已加载的模型** ⇒ 重复运行工作流不会变慢（热启动不降速）
  - 解码前清理可显著降低分块解码的峰值显存
- **工作流元数据**：`写入元数据`（默认开），把 prompt / workflow 写进文件——PNG 用私有 chunk，其他可写格式用 EXIF UserComment；**不支持元数据的格式自动跳过、不报错**
- **临时预览**：对齐原生 Preview Image —— 写 temp 目录、前缀加随机串、压缩级别 1、不进输出目录
- **文件名与前缀通配符**：`filename_prefix` 支持子目录（如 `images/ComfyUI`）、原生计数器 / `%batch_num%`，以及 `%date%` `%time%` `%date:yyyyMMdd%` `%time:hhmm%` 等占位符（与「Josia文本保存」同一套规则）
- **输出目录**：文件名框右侧的 **📁 选择** 会弹出文件夹选择器，选中后把该目录的**绝对路径**填进文件名框（之后存到该目录、脱离 output，序号自动递增不覆盖）；**📂 打开** 打开当前保存目录，未选择目录时打开 output
- **UI**：前端用 **DOM（CSS）面板**重排为「信息窗 + 6 行控件」，全部控件**统一高度、统一胶囊圆头**（非圆角矩形），原生功能逐项复刻不重新设计，便于跟随官方同步
  - **文件名行下方的信息窗**：实时显示 VAE 共享状态、当前分类与格式、解码方式、已保存文件数；高度随内容自适应
  - **预览 / 保存双选项胶囊**：位于文件名前缀之前，默认「保存」；切到「预览」后文件名前缀与目录选择**自动灰化**（仍可用右键图像 / 视频另存）
  - **三档分类胶囊**：「图像 / 视频 / 音频」切换分类；**切换 tab 自动选该类的默认格式**（图像→PNG / 视频→MP4 / 音频→FLAC），不必再手动挑一遍
  - **统一胶囊圆头 + 内联灰标签**：所有下拉 / 输入框 / 开关同高、两端圆头；选项内部显示灰色名称（如 `文件格式` / `解码方式` / `解码精度` / `分块大小`）；`VAE1` / `VAE2` 两个下拉**共同撑满整行**、随节点宽度自适应
  - **下拉浮层 + 全屏透明遮罩**：弹出下拉后，点击画布 / 节点任意空白都能**一键收起**
  - **无损 / 质量 / 压缩**列在「文件格式」之后、「元数据」之前；**无损默认开**（PNG 等无损格式即便无效也默认无损）；**质量步进 5 + 滚轮 + 上下箭头**（28 → 上推 30 / 下推 25，再 ±5），可手动输入
  - **音频加 WAV**：`WAV`（pcm_s16le 16-bit PCM，无码率、不写元数据、格式名不带 ⭐）；选 FLAC / WAV 等无损格式时 `音质` 下拉**灰化显示「无损」**
  - **分块参数为规范值下拉**：`分块大小 / 空间重叠 / 解码批次 / 帧间重叠`（见上文解码节）
  - **清理缓存长条胶囊**：开头文本「清理缓存」+ 关闭 | 轻度 | 深度（默认关），竖线分隔后再接「解码前 | 解码后」一组开关（默认解码前）
  - **底行圆点开关**：`写入元数据` 为圆点开关（点亮＝保存元数据，空心＝丢弃元数据）；`保存Latent` 同款圆点开关（默认关）
  - **节点宽度**：新建节点**默认宽 1080**（控件布局舒展）；手动拖拽时**最小宽度下限仅 320**，可自由收窄（「默认宽」与「最小宽」分离）
  - **面板上鼠标滚轮直接缩放画布**；胶囊色块按单元格实测几何定位（含 padding，不受画布缩放影响）
- **兼容性**：同时适配 ComfyUI 1.0 经典界面与 Nodes 2.0（Vue）界面，两套界面的控件显隐机制同时生效

### 15. Josia加载Latent（JosiaLoadLatent）
- **分类**：⚡️JosiaNodes
- **核心功能**：读取本地 `.latent` 文件送回下游，与「Josia媒体保存 → 保存Latent」配套 —— 那边存出 `.latent`，这里读回来并可放大后再送下游
- **OOM 保护闭环**：媒体保存开启「保存Latent」时会在 **VAE 解码之前**先落盘 `.latent`；解码爆显存后，用本节点重新加载、释放显存后单独解码续上，大幅拉高解码成功率
- **输入**：`.latent` 文件（下拉选择，或通过上传入口选任意位置的文件，不限 input 目录）
- **输出**：`Latent`（LATENT）
- **Latent缩放（可选，默认关）**：
  - 图像 Latent `[B,C,H,W]` / 视频 Latent `[B,C,T,H,W]`：只缩放**空间维度 H、W**，缩放后对齐到「对齐倍数」整数倍（默认 16，VAE / patch 通常要求 8 或 16 的倍数）
  - AV 混合 Latent（NestedTensor）：尝试**只放大视频路、不动音频路**再重新混合；重混合失败则友好报错终止（可关闭缩放原样加载）
  - 纯音频 Latent：不支持缩放，友好报错终止
  - **关闭缩放 ⇒ 潜空间严格原样透传，一个维度都不动**；对齐**向上**（ceil）取整，绝不因「就近取整」把潜空间缩小（信息裁掉不可逆）
- **信息展示**：选中文件后显示大小 / 形状 / 类型；支持一键打开上传目录
- **兼容性**：同时适配 ComfyUI 1.0 经典界面与 Nodes 2.0（Vue）界面

## 🎨 Josia编组增强（画布增强功能）
> 这不是节点，而是**画布层面的增强补丁**。在 **设置 → ⚡️JosiaNodes → 编组增强** 中启用；两个开关**默认关闭**，各自独立生效、互不影响。

| 设置项 | 作用 |
|---|---|
| **四角缩放** | ComfyUI 原生只有右下角能缩放编组，开启后补上 **左上 / 右上 / 左下** 三个角 |

- **四角缩放细节**：
  - 只改变编组边框的位置与尺寸，**内部节点绝不跟随移动**（与原生 resize 语义一致）
  - 拖拽时逐帧实时预览，并**跟随全局「对齐网格」设置**：开启对齐网格后，四角拖拽会像原生右下角一样自动吸附到网格
  - 悬停四角显示对应的 `nwse-resize` / `nesw-resize` 光标；四角标记的颜色随编组颜色变化
- **兼容性**：遵循 ComfyUI 官方安全规范，不含任何 `subprocess` / `eval` / `exec` 等系统调用

## 🎨 Josia模型列表增强（子文件夹着色、下拉已选项高亮）

> 这不是节点，而是**下拉列表的增强补丁**。在 **设置 → ⚡️JosiaNodes** 中启用；两项开关**默认开启**、**各自独立**（关掉其中一项不影响另一项）。

| 设置项 | 位置 | 作用 |
|---|---|---|
| **模型子文件夹着色** | 模型列表 | 在**所有**模型 / 文件下拉里，给带子文件夹的候选项加 `📂` 前缀，并按文件夹名分配一个**稳定颜色** |
| **下拉已选项高亮** | 下拉高亮 | 再次点开下拉时，把**当前已选中的那一项**涂成彩色底 + 白色文字，一眼看出上次选的是哪个 |

  - `krea2/xxx.safetensors` 显示为「**📂 krea2** / xxx.safetensors」——只给「📂 + 子文件夹」这一段上色，文件名保持原色
  - **同名文件夹永远同色**（跨重启、跨工作流一致），**同一个下拉内不会出现重复颜色**
  - 覆盖全部节点与原生节点的模型下拉，包括 1.0 经典界面（canvas 下拉菜单）与 Nodes 2.0 Vue 界面
- **高亮效果**：
  - 高亮底色**沿用该行的 `📂` 子文件夹颜色**（与着色体系完全一致），文字统一反白
  - 根目录模型等没有子文件夹的项，使用固定强调色（同样做了压暗处理，保证白字可读）
  - 作用于**所有**下拉（模型 / LoRA / VAE / CLIP / 采样器等），不要求候选里存在子文件夹
- **只影响显示，不改动实际值**：着色走官方 `widget.options.getOptionLabel` 显示钩子，下拉项的 `value` 与点击回调收到的仍是**原始模型路径**；高亮只写行内样式，不动 DOM 结构、不动 class。二者对执行与工作流序列化均零影响
- **说明**：1.0 经典界面中节点折叠态的下拉文字由 canvas 单色绘制，无法局部着色，因此折叠态只保留统一的 `📂` 前缀、不上色（高亮只作用于**展开后的下拉列表**）
- **兼容性**：纯前端 DOM 后处理，不含任何系统调用、不引入任何额外依赖

## 🛠️ 安装方法
1. 下载整个 `ComfyUI_JosiaNodes` 文件夹
2. 放入 `ComfyUI/custom_nodes/` 目录下
3. **（如使用 GGUF 模型）** 安装 [ComfyUI-GGUF](https://github.com/city96/ComfyUI-GGUF) 插件到 `ComfyUI/custom_nodes/`

7. **（可选）开关增强功能**：设置 → `⚡️JosiaNodes`，按需调整 —— 「编组增强 → 四角缩放 / 标题栏按钮」（**默认关闭**）、「模型列表 → 模型子文件夹着色」（**默认开启**）、「下拉高亮 → 下拉已选项高亮」（**默认开启**）

## ⚠️ 重要说明
1. 文本编码节点的 VAE 端口为可选输入，未接入时图生图模式自动降级为空 Latent
2. 图像缩放节点内置分辨率上限保护（400万像素），避免显存溢出
3. 缓存清理节点只清理无用显存/内存（不卸载模型、不清理系统文件缓存），全平台行为一致，安全无副作用
4. 分组控制、图像对比、流量阀门、种子节点、模型加载节点、多图加载节点均依赖前端 JS 文件，不可删除
5. 所有节点均已配置 `DESCRIPTION` 属性，在搜索节点界面和鼠标悬浮时可查看功能简介
6. **模型加载节点 GGUF 依赖**：加载 GGUF 格式模型需安装 ComfyUI-GGUF 插件；ckpt/safetensors/bin 格式完全独立运行
7. **多图加载节点**：`images_out` 批次输出在混合不同比例图片时会自动 letterbox（黑边居中），这是 PyTorch tensor batch 的数学限制；如需每张图独立的正确尺寸，请使用 `image_1` ~ `image_N` 单独输出端口
8. **文本保存节点**：`1.6.7` 起不再调用系统文件夹选择对话框，改用**内置文件夹浏览器**（后端标准库 `os.scandir` 枚举 + 前端浮层）；`1.7.0` 起恢复「打开输出目录」按钮（后端 `os.startfile`，Python 标准库、非子进程）。注：本包未承诺通过 ComfyUI 注册表的自动安全扫描，建议用 git clone / 手动拷贝安装
9. 文本列表和文本保存节点为纯 Python 标准库实现，不依赖前端 JS 文件，即使前端 JS 丢失也可正常工作（仅「选择输出目录」「打开输出目录」「复制路径」按钮需 JS 支持）
10. **编组增强默认关闭**：「编组四角缩放」与「编组标题按钮」两项默认关闭，需在 `设置 → ⚡️JosiaNodes → 编组增强` 中手动开启
11. **编组增强的四角缩放**只改变编组边框，不移动内部节点；若希望内部节点一起移动，请使用 ComfyUI 原生的编组拖动（拖标题栏）
12. **模型子文件夹着色 / 下拉已选项高亮默认开启**（`设置 → ⚡️JosiaNodes → 模型列表 / 下拉高亮`）：两项都只改显示、不改实际路径与取值，可随时分别关闭；若下拉里看不到 `📂` 前缀、颜色或选中高亮，请确认使用的是最新版前端文件 `web/js/model_folder_colors.js`
13. **图像对比节点重启后会空白**：对比图存于 ComfyUI `temp` 目录，而 `temp` 在服务**启动与退出时会被清空**；撤销 / 切换工作流 / F5 刷新都在同一服务进程内，所以能正常留存，但如果**重启过 ComfyUI**，旧对比图文件已不存在，需要重新执行一次（官方 Preview 类节点同理）
